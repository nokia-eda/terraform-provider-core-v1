# core-v1_auth_user (Resource)

Manages an EDA user. Identity fields use the EDA user APIs, group membership uses
`PUT/DELETE /core/admin/users/{uuid}/groups`, and the password uses
`PUT /core/admin/users/{uuid}/resetpassword`.

> **Local unreleased patch.** This behaviour is not part of any official release of
> the provider. See [auth_user patch notes](../auth_user_patch_notes.md), including the
> breaking changes.

## Passwords

The password is **write-only**: `password_wo` is read from configuration only and is never
stored in plan or state. It requires Terraform 1.11+ or OpenTofu 1.11+ (write-only attributes).

- Set `password_wo` together with `password_wo_version` (each requires the other).
- The password is applied on create and **only when `password_wo_version` changes**. To rotate,
  supply the new `password_wo` and increase `password_wo_version`.
- Limitation: changing the `password_wo` value without changing the version does nothing
  (Terraform cannot see write-only values), and out-of-band password changes are not detected.
- Prefer an `ephemeral = true`, `sensitive = true` variable as the source of the password.
- If `enabled = false`, the planned flag is re-enforced immediately after every password reset, before any group change; if that fails the apply stops (fail closed) and state records the actual flag.
- The legacy plaintext `password` attribute is **rejected** with a validation error.
- After `terraform import` no version is recorded; set `password_wo` and `password_wo_version`
  to intentionally reset the password.

## Built-in users are protected

`core-v1_auth_user` is for **new** users only. The built-in `admin` and `system-administrator`
users are never created, imported, read, updated or deleted by this resource; their lifecycle
(including credentials) belongs to the platform bootstrap/admin tooling. The guard checks the
**actual** username returned by the EDA API (not just the configured/state value), so it also blocks
`import` of a built-in UUID under another resource name, refreshes, updates and deletes. There is
no override switch.

## Groups

- `groups` omitted: membership is not managed by Terraform (state reflects the actual groups).
- `groups = [...]`: the full desired membership (list of group UUIDs). Order is preserved in state.
- `groups = []`: removes the user from all groups.

## Example Usage

```terraform
variable "new_user_password" {
  type      = string
  sensitive = true
  ephemeral = true
}

resource "core-v1_auth_user_group" "ops" {
  name        = "ops"
  description = "Operations"
}

resource "core-v1_auth_user" "ops_user" {
  username            = "ops-user"
  first_name          = "Ops"
  last_name           = "User"
  email               = "ops-user@example.com"
  groups              = [core-v1_auth_user_group.ops.uuid]
  password_wo         = var.new_user_password
  password_wo_version = 1
}
```

## Import

Import by user UUID (other values are rejected):

```shell
terraform import core-v1_auth_user.ops_user <user-uuid>
```

### Optional

- `password_wo_version` (Number) Version of the write-only password. Increase it to rotate the password. Required when password_wo is set (at least 1). Not set after import until an intentional reset.
